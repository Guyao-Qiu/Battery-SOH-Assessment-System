# Project Working Agreement

## Git checkpoints

- At the end of every completed user request that changes project files, verify the relevant changes and create a Git commit.
- Stage only files changed for the current request. Never include unrelated user changes without explicit approval.
- Do not create empty commits for diagnostic, explanatory, or read-only turns.
- Use a concise commit message that describes the completed outcome.
- Report the commit hash to the user so the change can be reviewed or reverted.
- Do not push, rewrite history, or discard changes unless the user explicitly requests it.
